# 名古屋全域の建物用途とCS1への接続

人とアンドロイドが同じ街で住宅、職場、店、道路、交通サービスを使い、導入条件を変えると就業や移動、店舗への配送がどう変わるかをCS1上で比較する。PLATEAUの建物IDを用途と街区に結び付けると、地域ごとの住宅や職場の条件を集計できる。

## 建物と用途地域

名古屋市の2022年度PLATEAUは376ファイル、738,178件の建物レコードを含む。実ゲームの描画カタログから書き出した738,033件の一意なIDを対象に、CityGMLの建物用途、用途地域の区画ポリゴンと国土数値情報の2022年行政区域を照合する。建物用途と行政が指定する用途地域は両方を保持する。用途地域の重複や未対応の地点は空欄として集計する。

| 2026年11月19日の照合 | 件数 |
| --- | ---: |
| 描画カタログと元のPLATEAU IDが一致 | 738,033 |
| 元データから建物自身の用途が判明 | 670,892 |
| 公式の用途地域に一意に対応 | 728,982 |
| 16区いずれかの行政区域に一意に対応 | 736,704 |
| 未配置または描画カタログ外の元データ | 145 |

公式資料は [PLATEAU CityGML配信](https://docs.plateauview.mlit.go.jp/datasets/citygml/) と [国土数値情報の行政区域データ](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-v3_1.html)。

## CS1の制約

導入済みのゲーム本体では建物枠は49,152件、道路セグメント枠は36,864件。既存セーブで開いている建設タイルは1枚で、実道路のうちゾーニング道路として確認した標準二車線道路は32区間だった。現在のセーブに原寸で全件を登録することはできない。

ゲーム側の建設範囲を25タイルまで広げる場合を想定し、元の接続を保つように道路の骨格を選び、元座標を約36%に縮めた道路計画を作成する。街区の住宅・商業・オフィス・工業は、同じ種類の複数のPLATEAU建物をCS1側の候補地に集約する。工場付き住宅などは用途別の候補を保持する。用途不明の建物に用途地域から仮用途を与えた場合は、明示的に記録する。

原寸の先行セーブで、開放済みタイルの標準二車線道路の近くにあるモデルは196件。道路と区画の正確な接続を確認した試験の [1棟の結果](plateau-zoning.md) は別に記録している。縮小案では道路1万6,000セグメント相当の骨格を選び、8,124件の街区・用途の組み合わせに対して2,228箇所の前面道路候補を作成した。

道路は外部高速道路まで1つの道路網として接続。元の建物IDの件数は各回の区画建設時に成功したTSVと用途対応表の突合結果で、複数の元の建物が1つのCS1建物を共有する。稼働を続けた後の有効なモデルID総数は別途集計する。水道設備を専用ノードで接続し、シミュレーション再開後に水不足と設備未接続の警告が消えたことを読み戻した。

住宅の空き世帯枠でアンドロイド176体の入居を確認。ゲーム内12月21日の記録では人2,174人、アンドロイド119体が入居し、人1,221人、アンドロイド66体に職場の登録があった。16区すべてで人とアンドロイドの入居・職場登録を区画の住民、雇用枠から確認した。アンドロイド43体に住居から職場への経路が記録された。配達の成立、長期間の人口維持、対照ケースとの雇用差は検証中。

区画追加後のセーブを再読込し、119体の住民IDを引き継いだ。同じセーブで空き世帯枠を再計測し、ゲーム内12月25日に16区でアンドロイド446体の入居を確認した。この時点で70体に職場の登録があり、14区でアンドロイドの就業を観測した。

ゲーム内1月5日の追加観測では、全16区で人とアンドロイドの入居・就業を確認した。人2,636人、アンドロイド411体が入居し、アンドロイド344体の職場登録、265体の通勤経路、17体の職場到着、236体の充電開始を記録した。稼働中も有効な登録建物は2,983棟。店舗の在庫追加はこの観測で0件だった。[区ごとの実測記録](evidence/native-coexistence-citywide-20261119.json)

ゲーム内2月12日、熱田区でアンドロイドが工場から店舗への配送を1件完了した。CS1の到着処理で、工場の在庫が869から769、店舗の在庫が13,439から13,539に変わった。工場への移動4件は経路が得られなかった。この観測では人口・就業・充電・配達件数をCS1標準の人口パネル内でも確認した。[配送の在庫記録](evidence/native-delivery-20261119.json)

### 道路・区画・インフラの拡張

OSMの道路を4,927区間追加した。読み戻した道路は計18,604区間で、全区間が外部高速道路につながる1つの道路網を構成した。追加区画の建設結果は、候補2,000件のうち1,820件。水道管と送電線も各781区間を増設した。

ゲーム内2月19日の稼働後、有効な登録区画は4,034棟。元のPLATEAU ID 738,033件との照合では、535,741件が分類済みの全用途、8,850件が一部の用途で有効な区画に対応した。161,144件は有効な区画との用途対応がなく、32,298件は用途が未分類。元の複数建物を用途別の街区内で集約しているため、対応したIDはCS1上で個別稼働する建物の棟数と異なる。

同じ観測では人4,391人とアンドロイド505体が入居し、人1,893人とアンドロイド389体に職場登録があった。全16区に両方の入居と就業があり、乗用車1,062台、貨物トラック673台、バス10台を記録した。水不足の警告は69件から0件に減った。道路未接続132件、電力網未接続255件、人手不足492件が残った。[建設・稼働の記録](evidence/native-network-expansion-20261119.json)

### アンドロイドを増員したときの就業

全域用MODとセーブの上限を512体から4,096体に変更した。増設後の街を新しいMODで読み込み、同じゲーム内時刻でアンドロイドの入居が495体から647体に増えた。目標は1,536体で、増員はCS1の空き世帯に制約された。

再開から4日18時間後、新規入居152体のうち110体が市内に残り、14体に職場、7体に通勤経路を確認した。新規組の職場到着はこの区間では確認できなかった。人の就業者は2,092人から1,936人へ、人の入居者は4,329人から3,852人へ変動した。増員しない条件での同期間の観測が、人の雇用に対する影響を評価するために残っている。[増員・就業の実測](evidence/native-employment-scale-20261119.json)

## 計測と再生成

Pythonのツールはデータと配置候補を書き出す。Python 3.12で実行し、用途地域と区の解析には NumPy、pyproj、Shapely 2.1以降を使う。道路と区画をロード済みの建設用セーブに反映するコマンドはPowerShellから実行する。

| ツール | 入力と出力 |
| --- | --- |
| `export_plateau_model_inventory.py` | CS1の描画カタログから建物IDと元座標をCSV化 |
| `assign_nagoya_wards.py` | 建物中心を2022年の公式区境界と用途地域ポリゴンに空間結合 |
| `join_plateau_building_use.py` | 2022年CityGMLの建物自身の用途とラベルを結合 |
| `plan_citywide_zoning.py` | 現在のCS1の道路・開放タイルを読み、建物中心の到達範囲を集計 |
| `plan_native_city_network.py` | OSM由来の道路グラフを入力し、接続を保ってCS1の枠内に収まる骨格を計画 |
| `plan_native_local_road_extension.py` と `compile_native_local_road_extension.py` | 既存道路への接続と、鉄道や他の道路との交差を照合して街路を補う |
| `plan_plateau_native_blocks.py` | 用途別の街区を集約し、計画道路沿いの候補地に割り当て |
| `plan_native_city_utilities.py` | 道路骨格から水道管と送電線の位置を計画 |
| `plan_native_utility_extension.py` | 稼働中の区画と水道・電力網を照合して不足する区間を計画 |
| `plan_native_utility_facilities.py` | 発電、給水、下水処理の設備候補を選定 |
| `stage_native_city_roads.ps1` | 区間の事前検査と建設の依頼を作成。`-Infrastructure` で水道管と送電線を対象にする |
| `apply_native_utility_facilities.ps1` | 設備を建設し、CS1が返す建物IDと位置を照合 |
| `plan_zoning_frontage_extension.py` | 区画のない街区について、敷設済みの道路沿いで空き地を探し、建設用TSVを作成 |
| `audit_active_plateau_zoning.py` | 稼働時に読み戻した有効区画と元のPLATEAU IDを照合 |
| `stage_native_city_zones.ps1` | 区画の追加を依頼。`-SavedRoadNetwork` で再読込した道路を使う |
