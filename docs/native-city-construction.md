# 名古屋全域のCS1建設

全市で人とアンドロイドが同じ住宅・職場・交通を使うため、建物の用途とCS1で構築する道路・区画を結び付ける。CS1の建物数と地図面積の制限に合わせ、建物ごとのIDを残しながら同じ用途の街区を集約する。既存の駅周辺のセーブから独立した、左側通行の `NagoyaCitywide-Construction` を使う。

## 配置データと実機の検証

道路の元データから13,648ノードと13,677区間を構築用に書き出した。データ上では全ノードがつながり、立体交差375箇所で中心線間に5m以上の高さ差を取り、勾配を16%以内に収めた。橋の幅やゲーム内の接続、車両挙動は実機で確認する。

用途別の区画候補は2,228箇所。738,033件のPLATEAUモデルを用途別に集約した741,740件の関連のうち、405,006件が候補に到達する。残り336,734件の用途には追加の道路や区画が必要。住宅・職場系以外の学校や設備は、その用途に合う施設の接続を別途確認する。

`NativeCityRoadBuilder` と `NativeCityZoneBuilder` はCS1の標準道路と区画をシミュレーションスレッドで作成する。実行前に都市・タイル・道路本数・入力ハッシュを照合する。`NativeCityLedger` がセーブに建物と道路の対応を格納し、`NativeCityRoster` が再読込後に有効な区画、入居者、職場登録、実際の通勤経路を区ごとに読む。ロード後の同一性確認に失敗した古いIDは、稼働集計に含めない。

## ローカルで再生成

下記は、使用するデータを用意するCLI。データは `H:/CS1-PLATEAU/nagoya-station` に置く。道路の高さ調整にはSciPyを使用する。

1. `tools/compile_native_city_roads.py` で原道路の区間と交差点をCS1形式に分割・整形する。
2. `tools/fit_native_road_clearance.py` で勾配と交差部の高さを調整する。調整済みの `native-roads-clearance-adjusted.tsv` を使う。
3. `tools/compile_native_city_sites.py` に調整済みの道路とPLATEAU用途のCSVを渡す。出力 `native-zoning-requests.tsv` は、CS1に構築済みの道路IDと照合してから適用する。
4. `tools/audit_native_zoning_gaps.py` で道路の追加が必要な街区を出力する。

ゲーム側は `citywide-zoning-v3/enabled.txt` を置き、名前を指定した新規都市だけで平坦化を行う。道路を適用する前に新規都市を別名保存し、`stage_native_city_roads.ps1` を実行モードなしで事前検査する。同じ入力で `-Execute` を指定して適用し、道路を保存したあと `stage_native_city_zones.ps1` に実際の道路の実行IDとセーブ名を渡す。観測には `road-runtime.json`、`zone-runtime.json`、`native-city-roster.json` を使う。

ゾーニング計画は、8列の配置行の末尾に道路の元ID、X座標、Z座標の3列を追加できる。1グループにつき最初の候補を含めて最大8箇所を、記載順にゲーム内で検査する。用途と空き区画の条件を満たした最初の道路で1棟を配置し、実際に使った道路IDを記録する。

`tools/plan_serviced_frontages.py` は、未対応の用途グループ、既設の道路、水道・電力、建物の一覧をもとに候補を作る。`--road` には道路計画と実機の施工記録の組を、道路追加の履歴に合わせて繰り返し指定する。`--output` の名前を `stage_native_city_zones.ps1` の `-RoadCommandId` に渡し、出力された `-plan.tsv` を適用する。

一般商品を扱う店舗を補う場合は、未建設か消失した一般商業区画だけを含む計画を作り、既存道路のセーブで `stage_native_city_zones.ps1 -SavedRoadNetwork -RequireGoodsShops` を使う。商業区画には、CS1が `Goods` を仕入れ品とするレベル1の建物を選ぶ。1×1の給油所への置き換わりを避けるため、この用途では2セル以上の店舗を使う。建物と用途指定が有効なPLATEAUグループは既設として扱い、配置先は道路に接する空きセルで照合する。

千種区と昭和区で各6棟、中区で5棟、中村区で4棟を配置した。建設直前と直後を同じゲーム時刻で照合し、既存717棟の商業施設と道路網を確認した。候補28件のうち7件は、元の道路に必要な幅と奥行きの空き区画がなかった。稼働後には、4区すべてで一般商品を受け入れられる店舗を確認した。[配置した建物IDと稼働確認](evidence/native-goods-retail-repair-20261119.json)

直線道路に面した区画に建てるときは、CS1標準の建設処理と同じく、区画の角度に90度を足す。既に建てた区画は、一時停止中の検証セーブで `stage_native_frontage_repair.ps1` を使って調べる。元の大きさと区画が一致し、回転後に記録上の道路へ出られ、CS1の衝突判定を通った建物を候補にする。回転後の地盤高をCS1標準の処理で事前計算し、高さが25センチを超えて変わる場合は対象から外す。`-Apply` を指定した場合は、CS1の建物移設処理で向きを変え、建物ID・建設世代・住民や従業員の枠・道路アクセスを照合する。

千種区、昭和区、東区、名東区、天白区、瑞穂区で46棟の出入口を修復し、別のセーブに保存した。建物IDと住民・従業員の枠を保ち、CS1が使う道路が各区画の記録と一致することを確認した。修復後の2回の観測では、合計14便が既に実績のある区に到着した。[建物ごとの角度と道路アクセスの記録](evidence/native-frontages-20261119.json)

## 分断された街路をつなぐ試験

`stage_native_employment_trial.ps1` の `-PedestrianLinksFile` には、既設の道路ノードIDを2つずつ並べたJSONを渡す。地表とノードの高低差、距離、接続数を検査し、CS1標準の建設判定に通った最初の候補1本を施工する。通勤の検証に使う住民は `-CommuteAuditIds` で指定する。成立した経路の区間IDを記録し、通勤に新設区間が含まれるかを照合できる。

施工前の街には32,699ノードがあり、今回のゲーム本体の標準建設上限32,256ノードを超えていた。地上の候補24件はすべて標準上限で拒否され、うち20件は衝突も報告された。絶対上限は32,768ノード。4候補の再試験では実際の空き枠を検査し、対象の施工呼び出し中だけ予約枠を許可した。衝突・接続・建設費の判定はゲーム本体に任せた。

地表の道路ノード22948と11953を歩行者専用舗装で結んだ。約185 mの連絡路は2区間で、両区間に歩行者レーンがあり、中間ノード4582を共有する。同じ住宅33828・職場30040のアンドロイドを同じ72時間観測すると、通勤の始点・終点は施工前と一致した。標準の通勤、歩行者専用レーンだけでの探索とも経路が成立せず、職場到着は0回だった。次の検証対象は、道路の歩道と歩行者専用路が交わるノードでの経路遷移。[建設判定、施工、通勤の実測](evidence/native-pedestrian-link-trial-20261120.json)

施工試験後の都市を `NagoyaCitywide-EmploymentTrial-PedestrianLink208m-Test` に別名保存した。保存時は32,700ノード、32,720区間。再読込後も同じ2区間が残り、歩道の経路探索に使用できることを区間ごとに検査した。

`-PedestrianLegsFile` で道路区間IDの組を指定し、CS1本体に歩行者レーン間の経路を24件要求した。新設2区間の間は往復できた。自宅側の道路6471から施工地点の道路35544までも往復できた。両端の接点では、隣接する既設道路を2区間ずつ選んで往復を試した8件がすべて失敗した。この交差部を通る歩行経路が作られないことを確認した。[再読込後の24件の経路試験](evidence/native-pedestrian-lane-transitions-20261120.json)

`-LinkWithRoadSidewalks` を指定すると、車道と歩道を持つCS1標準の `Basic Road` で同じ施工判定を行う。元のセーブをゲーム内の一覧から選び直し、開始時の道路網、居住・就業先、残高と72時間の観測期間をそろえた。最初の24候補はすべてCS1本体の衝突判定で施工を棄却された。対象の自宅と職場を結ぶ経路は成立せず、同じアンドロイドの職場到着は0回だった。[施工判定と対照比較](evidence/native-road-sidewalk-link-20261120.json)

既設道路43ノードをたどり、両側の道路を結ぶ候補194件から、距離、既設道路との交差、接続角度で24件を選び直した。同じセーブと観測時間で、これらもすべて衝突判定で棄却された。自宅側・職場側それぞれの歩道試験は通過し、両側を横断する往復2件は失敗した。対象の職場到着は0回。街全体では対照と両試験で21体が職場に到着し、配送は各8件だった。[選び直した24候補と経路の観測](evidence/native-road-sidewalk-link-20261120.json)

候補線と実機から読み出した既設区間の端点を平面上で照合した。48候補すべてが、元のマップにあった航空経路17687または19739と交差し、43候補は送電線とも交差した。航空経路の端点の座標は名古屋の道路施工前と一致する。[交差候補の集計](evidence/native-road-sidewalk-link-20261120.json)

8候補の施工判定で、CS1本体が記録した衝突区間と建物のIDを取得した。8件すべてに既設道路、4件に建物、2件に送電線が含まれた。航空経路が衝突記録に出た候補は0件。接続先32148を選んだ5件では、約7.66 mの行き止まり区間と、その付け根の道路2区間が共通して記録された。接続点を選び直すときは、この既設区間の幅と隣接建物を考慮する。[ゲーム本体の衝突IDと区間の読み戻し](evidence/native-road-collision-objects-20261120.json)

`-LinkWithRoadSidewalks` では `[開始ノードID, 終了ノードID, 曲線制御点X, 曲線制御点Z]` も指定できる。既設道路と建物の位置から曲線候補を絞り、短い行き止まり32148を外した24件を同じセーブで試した。24件とも衝突判定で止まり、新設は0本。すべての候補で端点から20 m以内に端を持つ道路が衝突記録に出た。対象の通勤経路と職場到着も72時間の比較で回復しなかった。87ノードの形状を照合して、ほぼ同じ中心線上にある13箇所の短区間の統合候補を記録した。統合の前には沿道の区画、建物の出入り口、交通と上下水道などを再確認する。[カーブ施工と通勤の記録](evidence/native-curved-sidewalk-trial-20261120.json)

`-LinkWithRoadSidewalks -LinkWithinRoadSegments` では、候補を `[開始区間ID, 終了区間ID, 開始側の区間内比率, 終了側の区間内比率]` で指定できる。曲線の場合は末尾に制御点のX・Z座標を追加する。地表の標準道路を対象とし、建物の出入りに使う区間と使用中の区画を保護する。

沿道照合では、13箇所のうち11箇所に近接する建物または記録上の区画参照があった。既設道路を残したまま別の接続点を探すため、道路区間178・8696と8796を結ぶ16案を同じセーブで試した。全案がMODの接続点事前判定で止まった。診断ログを追加して同じ16案を測り直すと、自宅側の区間178と8696はどちらも使用中の区画を持ち、職場側の8796は接続点としての事前判定を通過していた。ゲーム標準の施工判定は未実施。道路は32,718区間のままで、72時間に対象機体の職場到着は0回だった。街全体で職場に到着したアンドロイドは初回の試験と対照の両方で21体、完了した配送は各8件だった。[実行結果と同一条件の比較](evidence/native-segment-anchor-link-20261120.json)

中規模道路まで探索範囲を広げて選んだ自宅側6区間でも、18案すべてが使用中の区画を持つ区間に当たった。住宅側から6区間への往復12経路と、職場側から8796への往復2経路は、既存の歩道で成立した。両側を結ぶ往復2経路は失敗し、対象機体の職場到着は0回だった。自宅側の6区間には歩いて行けるため、次の施工候補は既存の区画を分割せずにその周辺の道路端へ接続できる線形から選ぶ。[候補・施工判定・14経路の実測](evidence/native-segment-anchor-link-20261120.json)

接続点の比率に `0` を指定すると、その側は既存道路ノードのIDとして扱う。例えば `[14898, 8796, 0, 0.57, -2399.915, -118.451]` は自宅側の既存ノード14898から職場側の区間8796の途中へ向かう曲線案。自宅側の区画を分割しない24案すべてがMODの事前判定を通った。ゲーム本体は24案すべてを衝突として棄却し、職場側の区間8796と11642が全件の衝突マスクに含まれた。2区間はノード21087を共有する。施工なしの72時間試験では対象の通勤経路は失敗し、職場到着は0回だった。[片側を既存ノードにした試験](evidence/native-segment-anchor-link-20261120.json)
